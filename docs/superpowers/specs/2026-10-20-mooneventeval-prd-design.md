# MoonEventEval v0.1 产品需求与设计（PRD）

版本：审阅稿 1，2026-10-20（America/Phoenix）。**状态：已完成文档自查，待用户批准书面规格；未进入实施。**

本文件取代同目录 `2026-10-20-event-evaluation-design.md` 的待审草案，是后续规格的唯一入口。方向选择不等于参数、接口或本规格获批。这里的示例是验收期望，不是产品运行结果。

## 1. 要解决什么问题

检测器给出的不是与参考标签逐行对齐的分类数组，而是一组可能重叠、重复、偏移的时间事件。要计算 TP/FP/FN，必须先决定“哪一个预测对应哪一个参考事件”。直接按 ID、行号、最近时间或遇到的第一个候选配对，都可能改变分数。

MoonEventEval 拟提供可嵌入的 MoonBit 评测库：接收同一录制中的参考事件和预测事件，依据显式的起止时间容差建立二分图，求最大基数一对一匹配，返回配对、误报、漏检和可复算依据。它实现成熟的事件评测方法，不主张算法原创，也不声称检测模型更准确。

首要目标用户是假定已能导出事件起止时间、需要核对检测结果的研究者和开发者；首版优先满足“本地文件跑一次”和“MoonBit 程序调用一次”。声音、传感器和科研是候选场景，尚无访谈、实际接入或第三方试用证明。

### 三个具体任务

| 任务与使用者假设 | 用户拿来的材料 | 需要完成的动作 | 可见结果与决策 |
| --- | --- | --- | --- |
| 声音检测开发者核算重复报警 | 同一段录音的参考事件，以及阈值已经选好的预测事件 | 一次评测，保留同时间不同 ID 的预测 | 一个参考最多贡献一个 TP；多报的预测列为 FP，可据此检查后处理是否重复触发 |
| 传感器算法开发者核查密集、重叠告警 | 同类别相邻/重叠参考区间和预测区间 | 采用完整匹配而非先到先配 | 给出不因贪心顺序少算的最大 TP 及具体配对；不由工具判断报警本身是否合理 |
| 研究者复核一项时间边界争议 | 公开或合成事件文件、声明的容差、指定的参考/预测 ID | 解释该事件对是否合格，再查看整体匹配中的身份 | 精确显示起止偏差、有效容差、合格与否；区分“可成为候选”与“进入当前最大匹配” |

这三项任务共用一个匹配核心，不拆成三个产品。不将同样的数据换三个行业名称当作需求验证。

### 价值假设及验证方式

- **H1：**比手写脚本更容易解释重复检测和竞争候选。验证：开发者用下文三组反例复算报告，能指出多报的是谁、为何不能重复计数；这是开发者复现，不算第三方反馈。
- **H2：**秒单位输入足够易用。验证：请一名愿意参与的使用者自行将一个自有的合成事件表改成示例 JSON，并在 10 分钟内运行、定位一个 FP；只有实际发生才记录为试用。未获联系授权前由用户本人征询，不代发消息。
- **H3：**MoonBit 生态需要这个限定核心。依据是相邻库行为比较和历史公开索引检索，尚不能证明需求规模或赛事不重复。组委会答复与外部接入均独立记录。

## 3. 方案取舍与首版边界

### 输入/数值方案比较

| 方案 | 好处 | 代价与风险 | 结论 |
| --- | --- | --- | --- |
| A. 十进制秒字符串 → MoonBit 精确整数时间 | 可直接写 `"10.05"`；不经过二进制浮点再猜边界；JSON 不丢大整数 | 需一个有界十进制转换器；用户必须给时间加引号 | **建议首版采用**，保留微秒精度，提供完整示例和明确错误提示 |
| B. 直接填写整数微秒（旧稿） | 核心最直观、容易与整数 oracle 对照 | 用户常持有秒值；人工换算易错，JSON 数字路径需审计 | 不作为首版文件格式；库内部仍用整数 |
| C. Float64 秒 | 接近常见科学工具和 sed_eval 输入 | 十进制边界可能因浮点表示改变判断；加 epsilon 又会引入新语义 | 不作为本项目权威时间契约，只在独立对照转换时使用 |

选择 A 不表示微秒具有医学或测量意义，只是一个有限精度的软件契约。超出六位小数时报错，不自动四舍五入。若实际需求要求更高精度，另行版本设计，不暗中改单位。

### P0：首版必须交付

1. 可独立调用的纯 MoonBit 核心，包含校验、时间转换、候选判断、最大匹配、计数和解释模型。
2. 一种 JSON 任务格式；`evaluate` 和 `explain-pair` 两项本地 CLI 操作，文本/JSON 两种报告。
3. 全局微平均、每类别及每录制汇总；全部 TP 配对与 FP/FN 列表；指定事件对的时间条件解释。
4. 三个完整合成案例、独立穷举及固定 sed_eval 版本的限定对照、复现说明与失败记录。
5. README、公开 API 说明、开源许可证及来源说明；本地检查、后续 CI、包外消费者复现与可发布候选。

远端创建、推送、正式发包和报名变更须另有明确授权；本 PRD 不授权这些操作。

## 4. 用户流程与易用性

1. 从完整示例复制任务文件；填写类别全集、录制 ID、参考/预测事件，时间以相对录制起点的秒表示。每项事件的 ID 仅用于追踪，不是配对主键。
2. 运行评测。默认先看到实际容差、TP/FP/FN、P/R/F1 和配对/未配对列表；需要机器复现时输出 JSON。
3. 对有争议的一对事件运行 `explain-pair`，核对具体时间条件；候选成立也可能因一对一竞争未被选中。
4. 修正调用方数据或显式修改容差后重新运行；工具不替用户删重复、移动事件边界或自动挑选更高分的规则。

以下命令为拟议接口，**当前不可运行**：

```sh
mooneventeval evaluate examples/duplicate.json --format text
mooneventeval evaluate examples/duplicate.json --format json
mooneventeval explain-pair examples/boundary.json --recording clip-01 --reference r1 --prediction p1 --format text
```

`--format` 默认 text。成功报告只写 stdout，诊断写 stderr；JSON 失败也向 stdout 写结构化错误。首版不主动覆盖输入或输出文件，用户可自行重定向结果。评测完成但分数为零、或事件对不合格，仍是成功执行，不作为进程失败。

### 最小完整输入示例

```json
{
  "schema_version": 1,
  "labels": ["alarm"],
  "config": {"collar_s": "0.2", "offset_ratio": "0.5"},
  "recordings": [{
    "id": "clip-01",
    "reference": [{"id": "r1", "label": "alarm", "onset_s": "10", "offset_s": "12"}],
    "prediction": [
      {"id": "p1", "label": "alarm", "onset_s": "10", "offset_s": "12"},
      {"id": "p2", "label": "alarm", "onset_s": "10.05", "offset_s": "12.05"}
    ]
  }]
}
```

预期摘要为 TP=1、FP=1、FN=0、precision=0.5、recall=1、F1=2/3；具体 p1/p2 身份以第 6 节固定遍历规则为准。文本必须用“所选配对”，不称“唯一真实对应”。

## 5. 输入与错误契约

### 结构与时间

- 一个 UTF-8 JSON 对象；`schema_version` 的值为 1。`labels`、`recordings` 必填；`config` 可省略，内部两个字段也可分别省略，默认值必须回显。
- `labels` 是非空、无重复的类别全集；只预测出现的类别也须声明。每个录制必须有 `id`、`reference`、`prediction`；两侧数组均可为空，录制数组也可为空。
- 事件字段固定为 `id`、`label`、`onset_s`、`offset_s`；未知字段、缺失字段、错误类型、未知类别、重复录制 ID、同录制同侧重复事件 ID 均使整份任务无效。首版返回首个错误及字段路径，不跳过坏行或输出部分指标。
- 时间与比例只接受 ASCII 十进制字符串，语法 `^(0|[1-9][0-9]*)(\.[0-9]{1,6})?$`。拒绝数字类型、正负号、指数、空白、NaN/Infinity 和多于六位小数；错误提示如“onset_s 应为秒字符串，例如 \"10.05\"”。
- 每个事件满足 `0 <= onset < offset <= 2592000` 秒（30 天），因此零时长拒绝；这不是已证实的需求上限，是本稿提出的安全范围。两侧同时间同类别、ID 不同的事件必须保留为独立事件。
- `collar_s` 范围 0–2592000 秒，默认 `"0.2"`；`offset_ratio` 范围 0–1，默认 `"0.5"`。零 collar 合法；默认值沿用参考方法的常见配置，不能自动宣称适合所有场景。
- ID/类别为非空有效 Unicode 字符串，精确比较，不 trim、不改大小写、不做 Unicode 归一化。两侧恰好同 ID 不增加配对资格。
- JSON 对象重名键沿固定标准解析器的后值覆盖语义处理；不同于事件数组内重复 ID 的拒绝。报告只代表解析后的任务，不能作为原始文本无重复键的证明。本轮已读本机 `json/parse.mbt` 确认赋值覆盖与深度参数，选定工具链后仍须用实际解析探针复核；不为此自写通用 JSON 解析器。

### 上限、失败及其理由

以下是待原型实测的 v0.1 硬限额，不能称为性能承诺。若要变更，先更新规格、边界测试与证据，不悄悄放宽。

| 项目 | 建议上限（含等号） | 理由/检查时机 |
| --- | --- | --- |
| 输入 | 8 MiB，JSON 容器嵌套深度 16 | 有界批处理；CLI 读入最多上限加 1 字节；解析前/解析中生效 |
| 录制/类别 | 1000 / 256 | 支持小批量和空录制；不生成录制×类别的空笛卡尔积明细 |
| 全任务事件 | 两侧合计 2000 | 首轮从旧稿 10000 下调；即使单个组最密集，跨侧检查也不超过 1000000 次 |
| 每个 ID/类别 | 256 个 Unicode 码点 | 限制无用负载；不等于 256 字节 |
| 匹配工作量 | 20000000 步 | 每次邻接边检查、搜索顶点进入及增广配对改写各算一步，操作前扣预算；跨组累计 |
| 序列化报告 | 16 MiB | 不导出整张候选图；先确认完整报告可输出，再写 stdout |

事件总数限制推导出候选检查和边数的上界，不再另堆可混淆的候选预算。时间 30 天和 ppm 比例的最大交叉乘积为 `2592000000000000000`，小于 Int64 上限；范围与类型必须在相乘前验证。限制工作步不等于保证墙钟时间或整个宿主进程峰值内存；原型须另记录实测。

CLI 退出码：0=完整评测/解释完成；2=输入、配置、参数或文件错误；3=资源限额导致未完成；4=内部非预期错误。错误模型包含 `status=failed`、稳定错误码、message、可用时的字段路径和限额/观察值；失败不得包含 completed、分数或部分配对。JSON 深度/文件大小等已声明资源限额超出统一为 3；合法时间范围外的数值为 2。

库接口用结构化 Result/错误表达同样区分，不通过 panic 表达普通坏输入。文件/进程故障属于适配层，业务语义仍在 MoonBit。

## 6. 匹配与解释语义

把时间精确转换成 Int64 微秒，把比例转换成整数 ppm，令 `c=collar_us`、`q=offset_ratio_ppm`，参考事件 r、预测事件 p 合格当且仅当：

1. 录制相同且类别精确相同；
2. `abs(p.onset_us-r.onset_us) <= c`；
3. `abs(p.offset_us-r.offset_us) * 1000000 <= max(c*1000000, (r.offset_us-r.onset_us)*q)`。

终点容差取固定 collar 与**参考**时长比例的较大值，不是预测时长、两者之和或较小值；边界包含等号。不要求额外 IoU 或区间相交，因此在极短事件/大容差下，不相交区间仍可能合格；文档必须说明这是所选评测规则的结果。

每个录制/类别独立求最大基数二分图匹配；每个顶点至多使用一次，TP 为配对数。不能把每个参考的任一命中累计为 TP，也不优化时间误差总和。不因事件重叠就合并或拒绝。

**确定性建议：**录制、类别与两侧事件分别按 ID/类别的 Unicode 码点字典序排序；逐参考事件搜索增广路径，邻接预测按 ID 升序，已占用预测可沿其参考继续搜索；每次搜索维护已访问集合，固定深度优先次序，使用显式栈规避递归栈风险。该遍历方案仍需独立穷举验证。报告数组按录制/类别/参考 ID/预测 ID 排列；同版本同语义的输入重排不改变所选配对、计数和解释。改变 ID 可能改变等价最优配对身份，不应改变 TP/FP/FN。

### 解释的范围

- 每个 TP 包含录制、类别、两侧 ID/起止时间、有符号时间偏差（预测−参考）、实际起点与终点容差、条件结果。
- 每个 FP/FN 包含原事件及合格候选数。候选为零标记 `no_eligible_candidate`；候选非零但未被选中标记 `unselected_in_maximum_matching`。后者不意味着它在所有最大匹配中都不可能被选中，也不必然是“重复检测”。
- `explain-pair` 在完整校验后，选取指定录制内两侧事件，共享同一候选判断函数，返回标签条件、起止条件及各自偏差/阈值。类别不同时仍可解释为不合格；ID 不存在是输入错误。它不运行整任务匹配、不输出 TP/FP/FN，也不把 eligible 当作已匹配。
- 输出时间以带 `_s` 的十进制字符串表示，去除多余尾零（整数保留一位以上数字）；负偏差可有负号。事件精度至六位小数；比例推导的有效终点容差可至十二位小数，精确展示而非取整回微秒。度量值 P/R/F1 才使用浮点展示。

## 7. 指标、空集和报告

`TP=配对数`，`FP=预测数−TP`，`FN=参考数−TP`。

`precision=TP/预测数`，`recall=TP/参考数`，`F1=2*TP/(2*TP+FP+FN)`。各自分母为零时各自输出 JSON null（文本显示“未定义”），不用 0、1 或 NaN 代替。F1 直接从计数算，不由可能为 null 的 P/R 推导。

| 参考数 | 预测数 | TP/FP/FN | P | R | F1 |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 0/0/0 | null | null | null |
| 0 | 1 | 0/1/0 | 0 | null | 0 |
| 1 | 0 | 0/0/1 | null | 0 | 0 |
| 1 | 1，无合格边 | 0/1/1 | 0 | 0 | 0 |

空参考录制的预测必须算 FP；遍历录制全集，不能只遍历有参考事件的录制。全局先累加计数再算微平均，不能平均各录制 F1。每类别汇总包含全部声明类别，每录制汇总包含全部录制；两者的计数合计须分别等于全局。

JSON 报告固定包含 `schema_version`、语义标识 `collar-max-cardinality/v1`、实现版本、`status=completed`、生效 config、summary、by_label、by_recording、matches、false_positives、false_negatives 和确定性的工作计数。所有事件恰在匹配或该侧未匹配列表中出现一次。首版不输出不受限的候选边全集。

输出不放运行时间、当前日期或本机路径来破坏可复现性；诊断与性能实测单独保存。固定字段/数组顺序，规范化十进制字符串；字节相同比较只在同一实现版本与序列化约定内要求。参考标注的质量由调用方负责，报告只能证明遵守所选评测规则。

## 9. 独立参考、数据与复现

### 三层互补验证

1. **人工/有理数时间判定：**最小边界案例和独立精确十进制/有理数 oracle 验证 eligibility，尤其检查比例容差产生分数微秒的情况。
2. **纯图穷举：**穷举小图全部可行一对一组合，验证最大配对数和合法性；不依赖 sed_eval，也不假定两种工具会选中相同最优配对。
3. **成熟工具对照：**固定 sed_eval v0.2.1，提交 `0cb1b6d11ceec4fe500cc9b31079c9d8666ed6eb`，`event_matching_type=optimal`，onset/offset 都开启，显式传入类别全集、collar、比例和空输出处理。每个录制都单独传入，包含预测独有录制。

sed_eval 本轮只读源码，尚未安装/运行；MIT 许可证已读取。它的终点规则与本稿数学形式相同，optimal 入口调用二分图匹配；不将此理解为与本产品已经兼容。参考环境在独立虚拟环境中固定解释器/依赖及哈希，若旧依赖不兼容，保留失败，不能修改参考算法后仍称原版对照。

### 共同口径和数值差异

- 第一组共有用例采用能同时精确表示的秒网格及可精确表示的 collar/ratio（如 0.125 秒网格、0.25 collar、0.5 比例），包含等号边界。
- 默认 0.2 与普通十进制随机用例仅把所有候选比较距离阈值大于 1 微秒的输入纳入非边界 parity；先用独立精确判定计算安全余量，不根据参考输出挑样本。保留抽样种子、排除规则与排除数量。
- 微秒精确边界由精确 oracle 裁定；另专门将这些案例输入 sed_eval，记录浮点边界可能不同的结果。差异须具体指向数值表示或统计口径，不能只写“浮点误差”而无最小反例。
- **已从源码确认的统计差异：**sed_eval 全局 `Nfp=Nsys−Ntp−Nsubs`、`Nfn=Nref−Ntp−Nsubs`，但其每类别 FP/FN 不扣 substitution。本项目把错误类别同时计作该预测的 FP 与该参考的 FN。因此类别明细可直接比；全局须显式用参考工具的类别计数汇总，或由其原始 Nsys/Nref/Ntp 派生共同口径，保留原始 Nsubs/FP/FN 并标出“投影值”。不能把参考原始全局 FP/FN 不同误报为匹配算法失败，也不能把投影说成原始输出一致。
- 同时间 A 类参考与 B 类预测的单对案例，本项目期望 TP=0、FP=1、FN=1；源码推导 sed_eval 原始全局会记 substitution。这只是源码推导，尚未实跑，必须在独立验证时留下双方原始输出。
- 比较共有口径 TP/FP/FN 与双方有定义的 P/R/F1；空分母/null、参考工具由 P/R 计算 F1 的路径、错误数据过滤策略、最优配对身份及额外 error-rate 不在完全一致承诺内。本产品空参考/空预测时 F1 的选择须单独测试，不能用适配器悄悄篡改参考结果。
- 任何不在预声明排除范围内且无法解释的差异阻断验收；不通过增加 epsilon、删失败样本或改期望来制造一致。

### 数据策略

首版必须案例全部自行合成并提交可编辑 JSON。随机数据由固定种子生成，保留生成配置和原始失败种子。三类行业案例可标“合成声音/告警/科研事件”，不得写成真实业务或临床试用。

公开数据仅作可选补充：使用前记录原始链接、版本/文件哈希、作者、许可、转换命令及再分发权；源码 MIT 不自动证明仓库内任意数据都可以重新分发。没有数据许可结论就不纳入包；首版验收不依赖下载音频/EEG 或大型数据集。不读取、复制或上传临床原始数据。

每次证据包含产品 SHA、语义版本、工具链/目标、输入和原始输出、命令、退出码、oracle/参考版本、比较范围及失败文件。证据须能在仓库外按说明重放；开发者自跑与第三方试用分开记录。

## 12. 组件设计与阶段顺序
