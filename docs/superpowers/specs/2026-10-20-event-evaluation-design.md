# MoonEventEval v0.1 设计规格

状态：方向①已由用户选择；本文件为待用户审阅的书面规格。产品代码、原型、外部对照、公开发布和赛事换题均未完成。

## 目标与成功条件

为有时间起止标注的事件检测任务提供可嵌入的纯 MoonBit 评测核心。用户提交参考事件、预测事件及容差，得到可复算的正确检出、误报、漏检和具体配对依据。

首要使用者为维护检测模型或标注结果的研究者和开发者。声音事件、传感器告警和科研事件检测是拟支持的三类使用场景，尚非已验证的用户需求；不声称已经用于真实课题组数据。

成功条件：核心在独立模块中可调用；三类关键反例正确；固定范围与 sed_eval 独立对照；CLI 输入输出可复现；能具体解释与已有 MoonBit 项目的核心差异。

工作名称暂定 MoonEventEval；仅表示本地项目名，不表示远端仓库或包名已注册。

## 首版边界

交付纯 MoonBit 库、JSON 输入输出 CLI、可运行例子、必要测试、CI 与文档。首版围绕同录制、同类别、起止时间容差下的一对一事件匹配。

不扩展信号检测模型、原始 EEG/EDF 读取、临床判定、通用标注治理、图像框评测、数据库对账、人工实体匹配或完整 Web 平台。首版没有宏平均、AP/ROC、IoU 评分或最小时间误差匹配等并列评测模式。

MoonBit 拥有输入业务验证、匹配规则、图构建、匹配计算、指标和报告模型。CLI 宿主仅做参数、文件及进程适配；Python/sed_eval 仅用于开发对照，不参与产品运行语义。

## 输入契约

首版以单个 UTF-8 JSON 文件表达完整评测任务，至少包含：

```json
{
  "schema_version": "1",
  "labels": ["event"],
  "config": {"collar_us": 200000, "offset_ratio_ppm": 500000},
  "recordings": [{
    "id": "demo-01",
    "reference": [{"id": "r1", "label": "event", "onset_us": 10000000, "offset_us": 12000000}],
    "prediction": [
      {"id": "p1", "label": "event", "onset_us": 10000000, "offset_us": 12000000},
      {"id": "p2", "label": "event", "onset_us": 10050000, "offset_us": 12050000}
    ]
  }]
}
```

- 时间为相对录制起点的整数微秒；单位由字段名固定，不自动猜测或浮点换算。公开库接口使用 Int64，JSON 必须可无损解码为该整数。
- 每个事件满足 `0 <= onset_us < offset_us <= 2592000000000`，即首版每录制最多 30 天。零时长点事件留待独立模式设计。
- `collar_us` 必须为整数，范围 0 至上述时间上限，默认 200000；`offset_ratio_ppm` 为 0–1000000 的整数，默认 500000，即 0.5。核心支持零容差；与 sed_eval 对照时仅使用其接受的正容差。
- recordings 允许 0–1000 个元素；每个录制均明确给出 reference/prediction 数组，允许空数组。没有参考事件的录制仍参与误报计数；不能因参考为空而跳过。没有录制时全局计数为零、三个指标均为 null。
- labels 为非空、无重复的类别全集；事件使用未声明类别时拒绝输入。录制 ID 唯一；事件 ID 在每个录制、每一侧内唯一。两侧使用相同 ID 不意味着应配对。
- ID/类别均精确比较，不隐式去空格或合并大小写。字段缺失、类型错误、事件 ID 重复或非法时间使整个任务无效，不静默过滤。
- 相同时间、相同类别而 ID 不同的事件保留为不同事件，尤其不能把重复预测预先去重。
- 首版只支持 schema 1 定义的字段；未知字段作为错误报告。JSON 文本同一对象重复键采用最后一次值，沿用本轮读取的标准库 parse_object 源码所示覆盖行为；不能宣称会拒绝对象重复键。此行为与数组内重复事件 ID 的拒绝规则分别定义；开发时须在固定工具链确认该解析行为。

## 配对规则和确定性

参考事件 r 与预测事件 p 有资格建立匹配边，当且仅当：

1. 来自同一录制且类别相同；
2. `abs(p.onset_us - r.onset_us) <= collar_us`；
3. `abs(p.offset_us - r.offset_us) * 1000000 <= max(collar_us * 1000000, (r.offset_us - r.onset_us) * offset_ratio_ppm)`。

第三项用整数交叉相乘比较，无除法取整或浮点 epsilon。30 天和比例上限保证所列乘积不超过有符号 Int64 范围。

每个录制/类别独立求最大基数二分图匹配：每个参考事件和预测事件至多出现于一个匹配对；目标是使正确检出数最大，不承诺时间误差总和最小。

输入先按 ID 的 Unicode 码点字典序规范排序；按固定顶点、邻接与增广遍历顺序获得可复现匹配。存在多个最优解时，只要求该实现的固定规则可复现，不宣称其选择具有身份真值意义，也不要求与参考工具选中同一组等价最优配对。

## 输出与统计

报告包含 schema_version、语义版本、实际配置、completed 状态、全局及各类别/录制的 TP/FP/FN、precision/recall/F1、全部匹配对、未匹配事件和匹配工作量统计。

- `TP = 配对数`，`FP = 预测数 - TP`，`FN = 参考数 - TP`。
- `precision = TP / 预测数`；预测数为零时为 JSON null。
- `recall = TP / 参考数`；参考数为零时为 null。
- `F1 = 2*TP/(2*TP+FP+FN)`；该分母为零时为 null。
- 全局指标先累计计数，再计算微平均。没有有意义的事件级 TN，不输出基于 TN 的 accuracy/specificity。
- 每个匹配对记录两侧 ID、起止时间、有符号起止偏差、容差与匹配条件。指标数值使用浮点展示，计数和是否匹配必须来自整数/离散结果。
- 未匹配事件区分“没有合格候选”和“有合格候选但未进入所选最大匹配”；后者不能表述为该事件在所有最优解中都无法匹配。
- 不跨录制、不跨类别配对。参考标注由调用方提供，报告不证明其客观正确，也不据此作临床结论。

## 三组必须通过的行为

以下均为设计阶段人工构造的验收样例，不是已运行结果。

| 场景 | 输入，单位秒（产品输入为上表整数微秒） | 必须结果 |
| --- | --- | --- |
| 重复检测 | r1=[10,12]；p1=[10,12]，p2=[10.05,12.05] | 默认配置下 TP=1、FP=1、FN=0；P=0.5、R=1、F1=2/3 |
| 贪心陷阱 | r1=[10,11]、r2=[10.3,11.3]；p1=[10.15,11.15]、p2=[9.85,10.85] | r1 可连 p1/p2，r2 仅可连 p1；必须 TP=2，选 r1-p2、r2-p1 |
| 精确边界 | r1=[10,12]；分别单独评测 p=[10.2,12.2] 与 p=[10.200001,12.2] | 前者合格；后者超过 onset 容差 1 微秒，不合格 |

另外必须覆盖：起止顺序非法、未知类别、重复 ID、空参考、空预测、全空任务内容、类别/录制隔离、同时间重复事件、打乱输入顺序、多个最优解、数量/计算预算边界。

## 组件职责

`model/validation` 处理输入、整数范围与结构化错误；`eligibility` 只判断一对事件是否有边及其依据；`matching` 只处理有预算的二分图；`evaluation` 分组并产生计数；`report` 生成稳定可序列化模型；`cmd` 适配真实文件和退出码。各组件均可单独理解和验证，不引入两套匹配语义。

首版核心为内存批量任务，不宣称大规模流式处理。JSON 输入最多 8 MiB、录制最多 1000、类别最多 256、事件合计最多 10000；每个 ID/类别最多 256 Unicode 码点。候选检查最多 2000000 次，合格边合计最多 1000000 条，匹配基本工作步合计最多 20000000 次。这些是首版固定硬上限，不提供预算配置字段；匹配基本工作步定义为每次邻接边检查以及每次增广路径顶点处理，均在执行前计数。

限额在输入或计算过程中检查，超限返回结构化失败且不附部分指标。CLI 退出码：0=评测完成（即使存在 FP/FN）；2=输入/配置/文件错误；3=资源预算不足、评测未完成。首版不增加未定义的质量门禁阈值。

## 独立对照和证据

参考工具固定为 [sed_eval v0.2.1](https://github.com/TUT-ARG/sed_eval/tree/0cb1b6d11ceec4fe500cc9b31079c9d8666ed6eb)，提交 `0cb1b6d11ceec4fe500cc9b31079c9d8666ed6eb`。本轮已读取公式与 MIT LICENSE.txt，并确认 tests/data/sound_event 公开夹具位置；尚未安装或运行该工具。采用其测试材料前仍逐项记录来源、许可与必要署名，不引入原始临床数据。

对照时固定 optimal 匹配、onset/offset 均开启，显式传入容差、比例与类别全集。比较 TP/FP/FN 及口径相同且有定义的指标；不比较不同最优解的任意配对身份、不同空分母默认值、额外 substitution/error-rate 口径。

本项目整数微秒契约与参考工具 Float64 秒存在边界数值差异风险。用可精确转换的测试子集和避开二进制边界歧义的随机用例验证共有语义；精确边界由独立整数/有理数判定验证。若出现浮点边界差异，保留最小反例并记为已解释差异，不改期望掩盖，不声称与 sed_eval 完全兼容。

匹配算法还需以小图独立穷举最大配对数验证，避免仅和同类算法互相印证。最终留存工具版本、输入、期望、真实输出、退出码、对照范围及失败记录。多后端只声称实际通过的目标；测试数量不能替代行为验收。

## 差异化与停止条件

MoonRow 处理业务主键下的表格快照变化；MoonLabelKit 公开定位侧重标注一致性；MoonMetricLab 公开接口覆盖一般机器学习指标；MoonDetEval 处理图像框/掩码；MoonEDF 处理 EDF/BDF 与事件窗口。首版差异证据必须落在时间容差、最大基数一对一事件匹配、重复预测处置、精确边界及逐事件依据。

这是一条成熟评测方法的 MoonBit 原生实现路线，不能声称算法原创或全球首创。公开检索未命中同核心不等于赛事不存在其他报名项目；同类能力若被进一步发现，要按实际功能重合重新判断。

产品代码前需用户审阅本规格；其后最小原型应先通过上述三组行为、小图穷举和固定参考工具对照，再扩大开发。若对照失败未解释、候选存在同核心公开实现，或无法写出独立价值，不继续堆界面和外围功能。
