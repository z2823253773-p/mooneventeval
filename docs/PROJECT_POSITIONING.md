# MoonEventEval 已实现范围与选题事实

代理根据仓库代码及本地运行整理，供本人理解和改写；不是本人申报书或实际答辩记录。本地工程复核和作者修复验证已完成，边界见[T8结果](reviews/2026-10-22-t8-results.md)。

MoonEventEval处理带标签的参考/预测时间事件，提供可读报告、稳定机器报告和指定事件对的资格解释。起止时间以十进制字符串输入，MoonBit使用整数微秒/ppm比较，保留等号和分数微秒终点容差；同录制同类构图后做最大基数一对一匹配。任务、时间、Unicode和资源错误都由稳定错误协议给出。

三个实际场景：

1. 重复预测：一参考、两合格预测，TP1/FP1/FN0，说明重复预测不会去重或重复占用参考。
2. 增广陷阱：r1可配p1/p2，r2只能配p1；增广将早期选择重排为两个合法配对，TP2。原版sed_eval optimal在这个案例同样TP2，不能宣传成超过它。
3. 精确边界：10→10.2的起点差恰好0.2，等号合格。解释显示有符号差、容差、类别/起点/终点通过标志；解释不声称该对一定被匹配选中。

可交付功能已包括：native文件CLI的evaluate/explain-pair、JSON/text输出、MoonBit公开工厂/评测/渲染API、资源限额、文件/输出错误处理、三完整案例、实际源包及解包后包外消费。输入仍仅自定义UTF-8 JSON/字符串时间，不支持直接DCASE TSV、CSV、sed_eval dict列表或stdin；这些增量仍在BACKLOG，不扩大宣传口径。

工程证据：小图独立部分注入oracle、精确有理数资格oracle、原版参考逐录制/类别/共同口径对照、四变形、实际资源边界、有限I/O故障注入、可编译算法mutation行为杀死、本地性能样本及端到端验收门。测试证明限定范围，不能据此承诺任意合法图的时间/内存或全部平台行为。

原版参考保留raw substitution/FP/FN并显式投影共同口径；具体binary64差异和零collar限制分开解释。产品无浮点时间比较不等于所有原版结果都一致。P2已公开仓库并成功运行双平台CI，见delivery/PUBLIC_RELEASE.md；当前没有外部用户反馈、注册表发布、组委会资格或本人讲解证据。PRD M2最小核心机器条件已完成；用户已取消自行复测。

已知限制：输入JSON重名键last-wins；含NUL的合法ID可评测/API解释，literal OS argv不能选中；超时部分输出取证仍有历史缺口。不能宣传为所有异常取证完整。
