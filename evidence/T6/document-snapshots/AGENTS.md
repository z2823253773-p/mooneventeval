# MoonEventEval 工作约定

- 用户以 Codex 为主；当前阶段先看 `docs/PROJECT_STATE.md`，再读其指定的有效计划、`docs/contracts.md` 和当前任务。需要时读取 PRD 对应章节，历史作废计划不作为当前指令。
- 一次推进一个明确任务，主实施者顺序写代码；独立评审/只读研究可在适用授权下交给子代理，不自动创建用户 chat，不让两名实施者同时改同一核心包。
- 任务边界更新 PROJECT_STATE：完成项、代码/被测 SHA、命令及退出码、证据路径、决定与作废项、阻塞、下一步。文件状态不能靠聊天摘要代替。
- 长日志落盘，只回传结论、退出码、证据路径及必要失败末尾；文档检查、编译探针、产品测试、独立对照、CI、发布证据分别标记。
- Codex 同一 chat 可连续处理清晰的小任务；上下文混杂或任务明显独立时由用户选择新 chat。新会话先核对实际 git 状态和磁盘契约，不依赖 /clear、/compact 或产品记忆还原事实。
- Claude Code 偶尔接手时读取同一入口，使用独立工作树，返回可审阅 diff 和命令证据；Codex 汇总、核对并更新状态。
- 新建议先进入 BACKLOG；改变已批准范围或验收门槛时先写明确修订并取得相应阶段批准，不悄悄删验收。
- 数学规则和产品语义在 MoonBit；Python只作开发验证。不访问临床原始数据，不改动旧 MoonReconcile。
- 远端创建、外发消息、报名变更、推送和正式发布仍须用户明确授权；遵守适用技能的阶段门槛。
